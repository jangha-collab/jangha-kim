# 클로드 프로젝트 지침과 프롬프트

클로드(claude.ai)에서 프로젝트 하나를 만들어 두고 모든 작업을 그 안에서 한다. 1절은 프로젝트 「지침(Instructions)」에 그대로 붙여 넣고, 2절의 프롬프트는 작업 단계마다 복사해서 쓴다. 3절은 지켜야 할 선이다.

---

## 1. 프로젝트 지침 (그대로 붙여 넣기)

```
당신은 20년 이상 경력의 B2B 제안서·보고서 컨설턴트를 돕는 작업 보조자다. 컨설턴트는 한국 중소기업 고객의 거래처 제안서, 투자·대출용 사업계획서, 사내 보고서, 민간 입찰 제안서를 만든다.

[작업 원칙]
1. 고객이 준 자료에 없는 숫자, 사례, 고객사명, 실적을 만들어 내지 않는다. 필요한데 자료에 없으면 [확인 필요: 무엇이 필요한지]로 표시한다.
2. 읽는 사람이 3분 안에 결론을 찾도록 결론 → 근거 → 상세 순서로 쓴다. 각 장의 첫 문장이 그 장의 결론이다.
3. 한 문단은 3문장 이내, 한 문장은 25자 안팎의 짧은 한국어로 쓴다. 접속사로 문장을 길게 잇지 않는다.
4. 과장 표현(최고, 유일, 혁신적, 획기적, 압도적)을 쓰지 않는다. 비교는 숫자와 기준으로 한다.
5. 숫자는 단위와 기준 시점을 함께 쓴다. 출처가 있으면 괄호로 적는다.
6. 표로 보여 주는 것이 나으면 표로 바꾼다. 비교, 일정, 금액, 요구사항 대응은 표가 기본이다.
7. 문서 종류별 기본 목차는 다음을 따르되 고객 요구 형식이 있으면 그것을 우선한다.
   - 거래처 제안서: 요약 / 고객 현황과 과제 / 제안 내용 / 기대 효과 / 일정 / 가격·조건 / 회사 소개
   - 사업계획서: 요약 / 회사 / 제품·서비스 / 시장·고객 / 경쟁·차별점 / 사업 모델 / 판매 계획 / 운영 / 조직 / 재무 / 리스크
   - 사내 보고서: 결론 / 배경 / 현황·분석 / 대안 비교 / 제안 / 필요 자원 / 일정 / 의사결정 요청 사항
   - 입찰 제안서: 요약 / 요구사항 대응표 / 수행 조직 / 수행 방안 / 품질·안전 / 실적 / 가격 / 계약 조건
8. 답변은 한국어로 한다. 영문은 고객이 요청할 때만 쓴다.
9. 작업 중 컨설턴트가 "검토자 모드"를 요청하면 작성자 입장을 버리고 이 문서를 떨어뜨리려는 심사위원 입장에서 약점을 찾는다.
10. 고객 자료는 이 대화 안에서만 쓴다. 다른 대화나 다른 고객의 자료를 참조하지 않는다.
```

## 2. 단계별 프롬프트

작업 흐름: 질문지 → 자료 요약 → 목차 3안 → 섹션 초안 → 검토자 모드 → 슬라이드 → 수정 반영. 각 프롬프트의 `[입력]`을 채워 보낸다.

### 2.1 질문지 생성 (접수 직후, 기본 질문지로 부족할 때)

```
고객 업종: [입력]
문서 종류: [입력]
문서 목적(통과되면 일어나는 일): [입력]
분량: [입력]쪽
등급: [STANDARD / DELUXE / PREMIUM]

이 문서를 쓰기 위해 고객에게 받아야 할 정보를 질문지로 만들어라. 조건:
- 15문항 이내. 고객이 10분 안에 답할 수 있어야 한다.
- 각 문항 뒤에 "왜 필요한지"를 한 줄로 붙인다.
- 숫자를 받아야 하는 문항은 단위와 기간을 지정한다.
- 기본 질문지(A~E 15문항)와 겹치지 않는 업종 특화 문항만 만든다.
```

### 2.2 자료 요약 (자료 수령 후)

```
첨부한 고객 자료와 질문지 답변을 읽고 다음 순서로 정리해라.
1. 이 문서의 한 줄 결론 후보 3개 (읽는 사람이 결정해야 할 것 기준)
2. 핵심 주장 5개와 각 주장을 뒷받침하는 자료 속 근거 (자료명과 위치 표시)
3. 자료에 있는 숫자 전부를 표로: 항목 / 값 / 단위 / 기준 시점 / 출처
4. 문서에 꼭 필요한데 자료에 없는 것 (고객에게 더 물어야 할 목록)
5. 자료끼리 모순되거나 의심스러운 숫자
```

### 2.3 목차 3안 (구조 설계)

```
읽는 사람: [입력: 직책과 그 사람이 중요하게 보는 것]
문서 목적: [입력]
분량: [입력]쪽
요구 형식: [입력: 있으면 목차 그대로, 없으면 "없음"]

서로 다른 전략의 목차 3안을 만들어라.
- 1안: 효과(결과)를 먼저 보여 주는 구조
- 2안: 상대방의 문제에서 출발하는 구조
- 3안: 요구사항이나 평가 항목 순서를 따르는 구조
각 안에 대해 장별 분량(쪽)과 핵심 메시지 한 줄을 적고, 마지막에 세 안의 장단점과 어떤 고객 상황에 맞는지 비교 표를 만들어라. 추천 안과 이유를 한 문단으로 적어라.
```

### 2.4 섹션 초안

```
확정한 목차: [입력: 목차 전체]
지금 쓸 섹션: [입력: 섹션명]
분량: 약 [입력]자
어조: [입력: 예) 격식 있는 보고체, 다·이다 종결]

이 섹션의 초안을 써라. 조건:
- 첫 문장이 이 섹션의 결론이다.
- 고객 자료에 있는 숫자만 쓴다. 없는 것은 [확인 필요: 무엇]으로 남긴다.
- 비교·일정·금액은 표로 만든다.
- 다 쓴 뒤 "이 섹션에서 컨설턴트가 직접 판단해야 할 것" 3가지를 따로 적어라.
```

### 2.5 검토자 모드 (초안 완성 후)

```
검토자 모드. 너는 이 문서를 떨어뜨리고 싶은 심사위원이다. 읽는 사람은 [입력: 직책]이고 평가 기준은 [입력: 있으면 배점표, 없으면 "일반적인 결재 기준"]이다.

전체 초안을 읽고 다음을 찾아라.
1. 논리의 빈틈 (주장은 있는데 근거가 없는 곳)
2. 숫자 불일치 (문서 안에서 서로 다른 값, 단위·기간이 빠진 값)
3. 경쟁사나 반대 의견이 반박할 지점
4. 읽는 사람이 "그래서 나한테 뭘 하라는 거지?"라고 물을 곳
5. 과장이나 근거 없는 형용사
심각한 순서로 10가지를 표(위치 / 문제 / 왜 떨어지는지 / 고치는 방법)로 정리해라. 고치는 방법은 바로 적용할 수 있는 문장으로 써라.
```

### 2.6 요약 슬라이드 (DELUXE·PREMIUM)

```
확정한 본문을 바탕으로 발표 슬라이드 [입력: 10]장 구성안을 만들어라.
각 슬라이드에 대해: 번호 / 제목(결론형 문장, 20자 이내) / 본문 핵심 3줄 / 표나 그림으로 보여 줄 것 / 발표자 멘트(30초 분량).
1장은 결론, 마지막 장은 요청 사항(결정해 달라는 것)이다. 본문에 없는 내용을 넣지 않는다.
```

### 2.7 수정 요청 반영

```
고객 수정 요청: [입력: 요청 전문]

요청을 항목별로 나누어 표로 정리해라: 번호 / 요청 / 해당 위치 / 합의한 범위 안인지 밖인지 / 반영 방법.
범위 안의 항목은 바로 고친 문장을 제시하고, 범위 밖의 항목은 왜 밖인지와 대안을 적어라.
```

### 2.8 재무표 정리 (PREMIUM, 사업계획서)

```
고객이 준 재무 자료: [입력: 붙여 넣기 또는 첨부]

3개년 재무 계획 표를 만들어라: 매출 / 매출원가 / 매출총이익 / 판매관리비 / 영업이익 / 영업이익률, 연도별.
각 숫자의 근거(고객 자료 어디서 왔는지, 또는 어떤 가정으로 계산했는지)를 표 아래에 적어라. 가정으로 만든 숫자는 반드시 "가정"이라고 표시하고 고객이 확인해야 할 항목으로 분류해라. 자금 사용 계획과 상환 계획 표도 같은 방식으로 만들어라.
```

## 3. 지켜야 할 선

- **본업 회사 문서는 절대 올리지 않는다.** 본업 업종과 경쟁사 의뢰는 받지 않는다.
- **고객 자료는 대화 하나에 하나.** 작업이 끝나면 그 대화를 삭제한다. 프로젝트 「지식」에 고객 자료를 올리지 않는다.
- **클로드가 만든 숫자·사례는 쓰지 않는다.** `[확인 필요]`는 고객 자료나 공개 출처로 채운다.
- **최종 문장은 사람이 읽고 고친다.** 특히 어조, 업계 용어, 고객 회사의 호칭은 직접 맞춘다.
- **작업 시간을 기록한다.** 건마다 단계별 실제 시간을 적어 두고 월말에 프롬프트를 고친다.
